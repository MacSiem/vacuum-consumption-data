# Portable consumption contract v2

Dataset v1 continues to package evidence records. Version 2 is the required contract for an application that imports a runtime-eligible profile: it adds completed-action identity, five separately balanced reservoirs, setting segments, transfer edges and external supply/drain flow.

`exposure_domain` describes the measured increment to which one coefficient applies. It is never an implicit whole cleaning mission. A `whole_cycle` coefficient means one complete, measured refill cycle in `ml/cycle`; an app's private area-based cycle estimate is not a portable v1 or v2 `whole_cycle` profile. Area and active mopping time describe alternatives for the same floor process and must not be added. A hybrid fit requires independently measured, identifiable components; one refill total cannot fit multiple free coefficients.

Only a counter increment or a terminal event with documented semantics can complete an action. A command acknowledgement, docking/return state, phase disappearance, or an inferred elapsed time cannot. An event must carry contiguous sequence, timestamp, setting-segment identity, source-contract identity and quantity provenance. It cannot be both completed and aborted; balances cannot go negative even temporarily. Aborted and partial operations remain replay events but cannot be billed as completed actions.

The five reservoirs are `dock_clean`, `dock_dirty`, `robot_clean`, `robot_dirty`, and `detergent`. Internal transfer edges are counted once at system level. A plumbed station uses explicit `external_supply`/`external_drain` edges. Dirty water is not derived from clean water. Detergent is not water: no grams-to-ml conversion is permitted without a separately verified concentration/density contract.

Time is one explicit axis: Unix epoch milliseconds. A replay supplies `baseline_observed_at_ms`; setting segments are contiguous half-open intervals `[start_at_ms, end_at_ms)` on that same axis, beginning at the baseline. Every event has a strictly increasing timestamp and sequence, must fall in its declared segment, and cannot predate the baseline. A live reader passes an explicit `now_ms`; the newest event must be no more than 120 seconds old and neither baseline nor events may be more than 5 seconds in the future. These are validation bounds, not a claim that any shipped source is live.

`schemas/portable-import-v2.schema.json` requires a versioned import envelope and source payload hash. `validate_import` projects records through the strict v1 schemas and reference checks, then requires `evidence_class=empirical` and `accounting_contract=v2` for every approved profile. `tools.contracts_v2.migrate_v1_payload` preserves v1 evidence and marks an old profile's accounting contract as `missing`; it never upgrades a coefficient to v2.

The nine source rows are exactly six Roborock and three Ecovacs source-documented, capability-dependent contracts. Every row carries model/SKU/firmware/integration/domain/key/unit scope. They are **not hardware verified** and cannot enable `validate_live_envelope`. A live physical stream requires a separately hardware-verified scoped contract, nonempty verification evidence and physical-ml provenance; changing a Boolean is not sufficient. A dedicated `synthetic_live_*_test_only` pair tests the positive live path offline and is never evidence, publishable measurement, or approved profile.
